# Autoplay introspection 20260804c-d

## 目的

ユーザー指摘の疑問点を解消するため、オートプレイの早期ターン判断を再検査し、need score を単一値ではなく上位パラメータへ分解した。

## 実装した上位パラメータ

`loveca_app/autoplay.py` に `_card_need_profile()` を追加し、ログ上の `need` を以下へ分解した。

- `keep`: マリガンや手札保持で残す価値。
- `exch`: ライブセット交換へ出しにくい度合い。低いほど流しやすい。
- `future`: 既存の将来ターン目標に対するプレイ価値。
- `dig`: 探索対象としての重要度。採用枚数が少ない直近目標札ほど高い。
- `rec`: リカバリ/進行補助効果の価値。
- `side`: 早期進行に絡みにくい対策枠判定。高いほど保持・交換保護を弱める。
- `flags`: `target_t+N`, `energy_boost_live`, `low_cost_summon`, `overcost_play`, `replaceable_low`, `sideboard_like` などの判定理由。

これにより、従来の「希少だから高い」だけの need score から、保持価値・交換コスト・探索価値を分けて確認できるようにした。

追加ログ 20260804e:
マリガン候補比較へ以下を追加した。

- `kept2=X/Y`: 候補が保持する2コスト枚数 / T2目標で要求される2コスト枚数。
- `redraws`: マリガンで戻して掘れる枚数。
- `t3_targets`: T3で必要な非2コスト候補。
- `t3_access`: その候補からT3目標へ到達できる概算確率。
- `t3_draws`: T3までに見込む探索枚数。

これにより、例えば `kept2=2/2 redraws=2 t3_access=0.698` と `kept2=1/2 redraws=3 t3_access=0.749` のような、T2安定とT3探索のトレードオフを候補単位で読める。

## 根本原因と修正

### 1. 君ここ T2/T3 が0%になる問題

原因:
空きステージ枠が残っている場合、配置探索が既存メンバーの置き換え候補を一切見ていなかった。これにより、`2-2` 盤面でアクティブエネルギー5のとき、7コストを2コストの上に置く差分登場が探索されず、T2 `7-2` へ進めていなかった。

修正:
配置候補を `空き枠 -> 置き換え` の順に広げた。ただし、空き枠へ通常登場できるカードは置き換え候補から除外し、5軸/10軸で不要に2コストを潰す副作用を防いだ。

確認:
君ここ seed401 / 200試行で、20260803t 比較:

- T2 stage cumulative: `0.0 -> 0.87`
- T3 stage cumulative: `0.0 -> 0.705`
- T4 stage cumulative: `0.0 -> 0.595`

ログ上でも `2-2 -> 7-2` が発生し、7コストの登場時だけ2コスト置き換えを使うことを確認。

### 2. 5軸/10軸の不要な置き換え

原因:
置き換え候補を広げるだけだと、空き枠に置けばよい4/5コストまで既存2コストを置き換える候補が混ざる。

修正:
空き枠があり、対象カードを空き枠へ通常登場できる場合は、既存メンバー置き換えをスキップする。差分登場でないとエネルギーが足りない場合だけ置き換え候補を残す。

確認:
5軸ログでは `2-2 -> 5-2-2` / `2-2 -> 4-2-2` が `main replaced out: none` になった。10軸でも `2-2 -> 4-2-2` が空き枠追加になった。

### 3. 10軸でDM+4を持った時に2コストを返しすぎる問題

原因:
10が見えていない10軸で、T3の10探索を重く見すぎ、`DM + 4` だけを残してT2の2コスト欠損を招く候補が上に来ていた。

修正:
10軸で `DM系ライブ + 4コスト` を保持している場合、2コストを1枚保持する価値を追加した。2枚以上は過保護にしない。

確認:
10軸 seed401 / 200試行で、20260804b 比較:

- T2 stage cumulative: `0.78 -> 0.805`
- T3 stage cumulative: `0.64 -> 0.655`
- T4 stage cumulative: `0.23 -> 0.235`

代表ログでは、初手 `4 + DM + 2` を保持し、T1 `2-2`、T2 `4-2-2`、T3 `11-2-2` へ進行した。

追加修正 20260804d:
ユーザー指摘により、T2で2コストが2枚必要なことを反映し、`DM系ライブ + 4コスト` を保持する10軸では2コストを2枚まで加点するよう変更した。

確認:
seed401 / 200試行で、20260804c 比較:

- T2 stage cumulative: `0.805 -> 0.83`
- T3 stage cumulative: `0.655 -> 0.66`
- T2 live cumulative: `0.215 -> 0.205`

代表ログでは、初手 `DM + 4 + 2 + 2` を保持し、T1 `2-2`、T2 `4-2-2`、T3 `11-2-2` に進行した。

内省:
2枚保持はT2ステージ達成を押し上げるが、戻す枚数が減るためDMや10/11探索の試行回数は減る。seed502/603では20260803t比でT2/T3 cumulativeが低下したため、単純な「常に2枚保持」ではなく、`DM+4+2+2` が既に見えている場合は2枚保持、10/DM/4のいずれかが欠ける場合は掘り直し重視、という分岐をさらに強める必要がある。

## 指標比較

20260804b から 20260804c の差分:

- 5軸: 全主要指標変化なし。
- 君ここ: 全主要指標変化なし。
- 10軸: T2/T3/T4 stage cumulative が小幅改善。

20260803t から見た大きな変化:

- 君ここのステージ進行は大幅改善。
- 5軸/10軸は20260803t比では一部低下が残る。主因は、need profile 導入とライブセット交換保護により、過去版より探索枚数が少ない場面が出ていること。

## 残る疑問点

- need profile の `keep` と `exch` は分離したが、ライブセット交換時には「現在の盤面で既に達成済みのコスト」と「将来もう1枚必要なコスト」をまだ完全に区別できていない。
- 5軸T3はまだ低め。T2達成直後に11探索へ切り替える方針はあるが、DMや5をどこまで保持し、どのタイミングで11以外を流すかの評価が粗い。
- 10軸は `DM + 4 + 2` 保持が改善した一方、T3の10/11到達に対する「10本命・11代替」の優先度がまだ同列気味。
- 10軸で2コスト2枚保持を強めると、T2ステージは改善しやすいが、DM/10/11探索枚数が減る。ログ上の `kept2/redraws/t3_access` で見えるようになったため、次はこの値を使って「T2の底上げ」と「T3本命探索」の重みを調整する。
- ライブ成功率はまだ粗い。ステージ進行が安定するまでは主指標にしない方針だが、ライブセットで成功可能なカードを残す/流す判断には最低限の成功見込みが必要。
- `sideboard_like` は「早期ターン目標に絡まない13以上」を暫定検出している。将来、13軸や特殊バトンタッチ型では誤判定しうるため、デッキから推定した進行テンプレートとの連動を強める必要がある。

## 次の改善候補

1. ライブセット交換で、手札・ステージ・次ターン目標から「余剰札」を明示的に算出する。
2. 5軸T2達成後は、ライブセット評価を11探索へ寄せる係数を強める。
3. 10軸T3は10本命/11代替を分け、到達経路をレポートへ出す。
4. need profile をマリガン保持用・ライブセット交換用・効果選択用へさらに分割する。
5. `kept2/redraws/t3_access` をスコア式にも戻し、T2が構造的ボトルネックでない場合は過剰保持を抑える。

## 20260804k: 理想着地点に対する課題洗い出しと初期対応

ユーザーの理想着地点:

1. どんなデッキでも、中間コスト枚数・エネルギー追加・コスト踏み倒し系効果からステージ進行を推定し、正しく回せる汎用性。
2. オートプレイを繰り返してもプレイがブレない頑健性。
3. プレイヤーとのCPU対戦で、対戦相手の公開状況を見てプレイをある程度変化させられる柔軟性。

現状課題:

- 汎用性: 既存の確認済みテンプレに強く依存しており、未知デッキでは構築内の中間コスト帯から自然なT2/T3進行を作る力が弱い。
- 汎用性: 「デッキに枚数が多い」だけで、そのターンのエネルギー制約を満たさない高コスト進行候補を作る危険がある。
- 頑健性: 同点評価の候補が複数あると、動的候補が確認済みテンプレを押しのける場合がある。
- 柔軟性: `suggest_autoplay_action` は相手成功枚数/ウェイト人数などの公開情報をほぼ見ていなかった。
- 柔軟性: 相手が先行しているときに高スコアライブを狙うか、DMなどの進行札を成功させるかの切り替え基準はまだ粗い。

実装:

- コスト分布から動的な進行候補を生成する入口を追加した。
- 動的候補はT2に10/11を直接要求しないよう、T2中間コストを4-8帯に制限した。
- 4コスト+DM系エネルギー追加がある場合、`2-2 -> 4-2-2 -> 10/11` 系の候補を作れるようにした。
- 既存の確認済みテンプレと同点なら、確認済みテンプレを優先するようにした。動的候補は未知デッキ用の補助候補として残す。
- CPU action suggestionで、相手成功枚数/相手ウェイト人数/既知手札枚数から `public_context` を作り、ライブセット理由と高スコア優先判断へ反映する入口を追加した。

確認:

- 5軸 seed401 / 200試行: 20260804h比で主要指標差分0。推奨は `2-2 -> 2-5-2 -> 2-11-2` を維持。
- 10軸 seed401 / 200試行: 20260804h比で主要指標差分0。推奨は `2-2 -> 2-4-2 -> 2-10-2` を維持。
- 君ここ seed401 / 200試行: 20260804h比で主要指標差分0。推奨は `2-2 -> 7-2 -> 13-2` を維持。
- 一度は動的候補が `T2 11-2-2` や `13-2-2` をメイン目標化して大幅悪化したが、エネルギー制約と同点優先度の修正で解消した。
- fake LIVE_SET stateで、相手成功枚数1/自分0/相手ウェイト0の場合、`public_context.pressure=behind` として認識し、ライブセット理由に相手公開状況を反映することを確認。

次に実プレイ上で確認したいこと:

- 相手が先行しているT2で、DMを成功させる進行と高スコアライブを成功させる進行が両方見えている場合、どちらを優先するか。
- 相手がウェイト2以上で明らかに遅れている場合、ライブ成功率より手札交換/次ターン進行をどれくらい優先してよいか。
- 未知デッキで「T2に使う中間コスト」が5/7/10以外の場合、どのターン目標を自然と感じるか。

## 20260804l: CPU対戦の公開状況補正を千秋楽限定へ修正

ユーザー方針:
相手が千秋楽、つまり成功ライブカード2枚でない限り、自分の進行を崩してまで無理に高いスコアを狙う必要はない。

修正:
- CPU action suggestion の相手公開状況評価に `opponent_finale` を追加した。
- 高スコアライブ目標へ補正する条件を、相手成功枚数2枚以上の場合だけに制限した。
- 相手が先行または動けそうでも千秋楽でない場合は、理由文を「進行を崩さずステージ目標を優先」へ変更した。

確認:
- fake LIVE_SET stateで、相手成功1枚/自分0枚/相手ウェイト0の場合、live targetは通常の `3+` のままになり、理由文は「千秋楽ではないため、進行を崩さずステージ目標を優先」になった。
- 同じstateで相手成功2枚にした場合、live targetが `5+` へ上がり、理由文は「相手が千秋楽のため、手札内で狙える高スコアライブを優先」になった。

次の観察点:
- 千秋楽時にもDMなどの進行札をどの程度残すべきかは、CPU対戦ログで別途確認する。
- 相手が1成功で先行しているだけの局面では、まず自分のT2/T3進行が崩れていないかを優先して見る。

## 20260804m: 千秋楽時の成功候補ライブをスコア目標へ揃える

課題:
前回修正で、相手が千秋楽の時だけlive targetを高スコアへ補正するようにした。ただし、交換候補にDMと高スコアライブが同時に含まれる場合、内部の `live_for_success` がDMのまま残り、理由文が `live target 5+ / selected live score 3` のように読めてしまうケースがあった。

修正:
- 千秋楽補正で `score_priority_mode=finale_pressure` を付与した。
- このモードの時は、交換候補内に目標スコアを満たすライブがあれば、それを成功候補として優先するようにした。
- 通常時や相手成功1枚以下の時は従来通り、DMなどの進行支援ライブを成功候補として扱う。

確認:
- fake LIVE_SET stateで相手成功1枚の場合、`live target 3+ / selected live Daydream Mermaid score 3` のまま。
- 同じstateで相手成功2枚の場合、`live target 5+ / selected live ミラクル STAY TUNE！ score 5` になった。
- payloadの交換候補自体は同じ3枚で、千秋楽時だけ成功候補の解釈がスコア目標側へ切り替わる。
