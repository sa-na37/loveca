## 観察1: 君ここは特殊登場シグナルが実行に接続されていない疑い

君ここはレポート上では以下を検出できている。

- `PL!-pb1-018 矢澤にこ` を `overcost_member_play,low_cost_summon` として検出
- T2 accepted target: `7-2 / 7-2-2`
- Target Cards And Routes でも `矢澤にこ route=手札から通常登場 / 登場時に追加2コスト登場候補` と表示

しかし実際のtrialでは、T2開始時にactive energyが5あり、手札に7にこがある局面でも、main stageが `2-2 -> 2-2` のまま変化せず、`missing 7` で失敗している。

具体例:

- `decision_trace_20260803t_kimi_seed401` Trial 2
- T1で `2-2`
- T2開始時に手札へ7にこがある
- T2 active energyは5
- main played/replaced inは `none`
- resultは `missing 7`

疑問:

- `overcost_member_play` / `low_cost_summon` は目標推論にだけ使われ、実際の `_improve_persistent_stage` のプレイ可能判定に使われていないのではないか。
- 7にこを「支払えるコスト以上のメンバー登場」扱いする場合、ステージ置換/追加登場の支払い評価をどのように一般化するべきか。
- 7にこ成功時の追加2コストは、virtual low summonとして判定するだけでなく、次ターン以降の実ステージ維持に反映すべきではないか。

優先度:

- 高。君ここのT2以降がほぼ0%になっており、現状の君ここ評価は信頼できない。

## 観察2: 5軸はT2未達時のライブセット方針がまだ弱い

5軸はT2 cumulativeが約85%まで出ている一方、T2未達は `missing 4 / missing 2` が主因。T3は `missing 11` が安定して約40-48%残る。

気になったtrace:

- Trial 1で初手にDMと2、11があり、マリガン後もDMと11が残る。
- T2時点で `2-2` から進めず `missing 4`。
- そのT2ライブセットでDMを保持したまま、2コストを1枚だけ交換している。
- その後T3も `2-2` のまま `missing 11`。

疑問:

- T2に4/5が見つからず目標未達になった場合、ライブセットは「本来のT3 11探索」ではなく、まずT2ブリッジ復帰用の4/5探索へ全力で寄せるべきではないか。
- DMを持っていても4/5が無い場合、DMを守るより、DMをセットして成功期待を取りながら山を掘る方が良い局面があるのではないか。
- T2目標達成済みなら11探索、T2未達なら4/5復帰探索、という分岐を明示すべきではないか。
- 11をマリガンで返した/守ったケースの成否を、T2達成済みか未達かで分けて集計できないか。

## 観察5: live cumulative / combined cumulativeはまだ主指標にしづらい

今回の修正で、ライブ成功判定は「実際にlive_for_successとして選んだライブ」を見るようになった。その結果、以前よりlive cumulativeが大きく下がっている。

現状の問題:

- ライブ成功率はまだ粗い候補判定で、エール期待値・ブレード/ハート・ステージ効果を精密に見ていない。
- live score targetは「成功させたいライブ」ではなく、「そのターンに何点ライブを置いたか」に寄りすぎている可能性がある。
- ライブセット交換は最大3枚の手札交換でもあるため、「成功させるために置くライブ」と「探すために置く/流すカード」を同じ枠で評価している。

疑問:

- 当面の比較指標はstage cumulativeを主、live cumulativeは参考に落とすべきではないか。
- live targetはターンごとの固定スコアではなく、その時点の盤面から成功しうるライブ候補の期待値で推定すべきではないか。
- DMのようなエネルギー追加ライブは、スコア達成ではなく進行達成補助として別枠評価にするべきではないか。

## 観察6: need scoreの表示だけでは判断理由が追えない

traceにはneed scoreが出るが、実際には以下の価値が混ざっている。

- マリガンでキープする価値
- ライブセット交換に出すコスト
- 未来ターンに引きたい価値
- 今ターンの盤面復帰に必要な価値
- 進行札ではないが、少数採用で高く見えてしまう価値

疑問:

- `keep_value`, `exchange_cost`, `dig_target_value`, `recovery_value`, `sideboard_like` を分けてtraceへ出すべきではないか。
- 特にT2未達時は、未来のT3札より現在未達の復帰札を優先するモードが必要ではないか。
- 交換した理由を `duplicate`, `target_already_met`, `sideboard_like`, `dig_missing_4`, `dig_missing_11`, `live_success_candidate` のように明示できないか。
