### 実装方式メモ

- デッキ下を見る効果は、既存のデッキ上確認と同様に pending を経由する。未公開情報を即時ログだけで処理せず、選択後に `put/keep` または `green/keep` を解決する。

- 名前一致後続は、選んだカードのカード名を runtime DB から確認する。カード番号専用分岐は追加していない。
- 任意登場は既存の `hand_member_to_empty_area_place` を再利用し、任意効果時だけ `skip` を受けるようにした。
- 相手エネルギー比較は `_opponent_energy_count_known/_opponent_energy_count` を使う。未知なら確認pending、既知なら自動で条件判定する。

## 2026-08-25 追加調査: PL!-pb2 商品ページ到達性とSPpb2汎用経路

### PL!-pb2 商品ページ到達性

- wikiの商品ページ「プレミアムブースター ラブライブ！ DUO」は、収録カード一覧として11行を持つことを確認。
- 内訳は、確定番号の新規カード3行、番号未確定の新規ライブ5行、再録3行。
- 現行DBに入っている新規カードは以下3件。
  - 星空凛＆小泉花陽
  - 高坂穂乃果
  - 僕たちはひとつの光
- 更新アプリ側の未到達原因は、番号未確定行が `PL!-pb2-???` 形式で、従来のカードリンク抽出が「3桁以上の確定番号」を前提にしていたため。DB本体はカード番号を主キーにしているため、番号未確定5件をそのまま登録すると同一キー衝突を起こす。
- 対応として、番号未確定行はDB本体に入れず、商品ページ監査情報 `unresolved_card_rows` / `unresolved_card_row_count` として保存するようにした。番号確定後は通常のカードページリンクとしてDB更新対象に入る。
- プレリリース期間中の商品ページは、未発売商品すべてを毎回踏まない。前回監査で「カード個別ページから公式X投稿へのリンク」が検知された商品だけ、キャッシュが存在していても同じURLへ新規取得を試みる。
- 未発売商品の中で最も発売日が近い商品は、カード発表開始を検知するため短TTLで商品ページを再確認し、商品自身のカード番号に絞って個別ページ上の公式Xリンクを確認する。その他の未発売商品は前回registryを再利用する。
- 2026-08-26実取得確認: 公式ポスト集約ページをネットワーク更新し、PBLL02について公式ツイート対応13件を取得。うちDB既収録2件、DB未収録preview-only 11件。preview画像は13件すべて `preview_card_images/PBLL02/` へ保存済み。
- 2026-08-26実取得確認: PBLL02商品ページを新規取得し、カードリンク20件を確認。個別カードページの公式Xリンクプローブは商品自身の `PL!-pb2` リンクだけへ絞るよう実装修正済み。実ネットワーク確認ではWIKIWIKI 429により個別ページ側の公式Xリンク検知は途中失敗したため、当日の画像取得は公式ポスト集約ページ経由で完了。
- 429対策として、商品ページ/カードページで429が出た場合は既存キャッシュがあればキャッシュに退避し、未キャッシュページは失敗理由を監査に残してスキップする。発売済み商品の再チェックは「発売後初回の定期更新」を `regular_checked_on` で記録する方式へ寄せた。
