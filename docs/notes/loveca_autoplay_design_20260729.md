# Loveca Autoplay Design 20260729

## 目的

オートプレイは、デッキを自動で試行し、目標達成率と構築改善案を確認するための補助機能として実装する。
実装は3段階に分ける。

1. 汎用的なプレイ方針を導入したモデルの作成
2. 達成目標の設定によってモデルへ補正を加える機能
3. 繰り返し試行後、達成率を上げる構築改変を探索する機能

初期実装では、シミュレータの状態を直接進める前に、デッキリストからコスト進行テンプレートとの相性を評価する `stage1_policy_template` レポートを作る。

## 参考

- さーな「〖ラブカ〗コスト進行の基礎〜制限後の構築考察へ向けて〜」
- URL: https://note.com/sanapoke/n/n6d74b91d20db

参考記事から、序盤の代表的な進行をテンプレートとして採用する。

- `4 -> 9 -> 15単騎`
- `4 -> 7-2 -> 13-2`
- `4 -> 2-4-2 -> 2-10-2`
- `2-2 -> 2-4-2 -> 2-10-2`
- `2-2 -> 2-5-2 -> 2-11-2`
- `2-2 -> 2-7 -> 2-13-2`

## Stage 1: 汎用プレイ方針モデル

### 実装範囲

- デッキ内のメンバーコスト分布を集計する。
- デッキ内のライブスコア分布を集計する。
- 代表的なコスト進行テンプレートごとに、必要コストの充足度を評価する。
- 3ターン目までの進行を、5〜10コスト帯の厚みで補正する。
- 4ターン目以降の進行を、15コスト以上の厚みで補正する。
- コスト軽減や特殊なバトンタッチ形式を、カード番号専用ではなく効果文由来の汎用シグナルとして拾う。
- アプリメニューへ「オートプレイ」を追加し、デッキごとの方針レポートを表示する。
- モデルデッキ検証用に、人間可読のMarkdownレポートを出力できるようにする。

### 実装ファイル

- `loveca_app/autoplay.py`
  - オートプレイ用の副作用なしロジック。
  - `COST_PROGRESSIONS` に進行テンプレートを定義。
  - `build_autoplay_deck_report()` でデッキレポートを生成。
- `loveca_app/core.py`
  - `AppState.autoplay_deck_report()` でデッキ読込、検証、レポート生成を接続。
- `loveca_app/web.py`
  - `/autoplay` 画面を追加。
  - ホームメニューにオートプレイ入口を追加。
- `loveca_autoplay_report.py`
  - 指定デッキまたは全試行可能デッキの方針レポートを `docs/reports/autoplay/` へ出力。

### 現時点の評価仕様

- 各テンプレートの必要コストを集計し、必要枚数に対する採用枚数で充足度を出す。
- 目安として、各必要コストは「必要回数 x 3枚」程度あると安定寄りに評価する。
- `2-2` 進行は序盤の盤面スタッツを作りやすい前提で軽いボーナスを入れる。
- 5〜10コスト帯は3ターン目までの中継安定性として加点する。
- 15コスト以上は4ターン目以降の勝ち筋再現性として加点する。
- 効果文にコスト軽減系の語があるカードは、通常より高コスト接続しやすいシグナルとして扱う。
- 効果文にバトンタッチがあり、かつ高コスト寄りのカードは、特殊バトンタッチ進行のシグナルとして扱う。
- 2ターン目までのプレイ枚数が多い進行は手札消費リスクとして軽い減点を入れる。
- この評価はプレイング実行ではなく、方針候補を並べるための初期モデルである。

### 試行モデル 20260729a

`stage1_policy_template` の評価結果を使い、構築内容から到達したい各ターンの盤面コスト形を推定する簡易試行モデルを追加した。

方針:

- 3ターン目までは、推奨された序盤コスト進行を目標形にする。
- 4ターン目以降は、15コスト以上や特殊バトンタッチのシグナルを含む後半進行を優先する。
- 各試行では初期手札6枚から開始し、2ターン目以降に1枚ずつドローする。
- 各ターン、手札内で目標形に最も近いメンバー組み合わせを選ぶ。
- 完全一致率、平均ステージコスト、よく出た進行、サンプル進行をレポートへ出す。

この段階では、実シミュレータ engine を直接進行させる完全オートプレイではない。構築から見た「目標形への到達しやすさ」を粗く比較するためのドライランである。

実行例:

```bash
cd /Users/tekitou/Desktop/gsim/loveca

python3 ./loveca_autoplay_report.py --recent 3 --trials 500 --seed 29 --turns 4 --outdir docs/reports/autoplay
```

次段階では、ここで選んだプレイ方針を実 engine の選択処理へ渡し、実際のドロー、プレイ、効果処理、ライブ成否まで含めた試行へ拡張する。

  - `バトンタッチして登場した場合` のような受け身条件だけを持つカードは、特殊バトンタッチ札として扱わない。

まだ近似であり、ライブ成功率、必要ハート、相手スコア、控え室形成の厳密な再現は次段階の実 engine 接続で扱う。

### 試行モデル補正 20260729e

マリガン、ライブセット、配置優先順位を見直した。

- マリガンはT1〜T3の達成率最大化を目標にする。
  - 3枚採用の10コストなど、T3目標に必要で採用枚数が少ないカードは初手にあれば残しやすくする。
  - 2コストのように採用枚数が多く引き直し期待が高いカードは、近いターンの必要枚数を超えた分を戻しやすくする。
- ライブセットはライブカード1枚固定ではなく、最大3枚の手札交換として扱う。
  - 非ライブカードも交換対象にする。
  - 直近目標に不要で、後続目標にも薄いカードを優先して交換する。
  - Daydream Mermaid系のエネルギーブーストカードは、必要ターンまでは交換せず、`2-4-2` 代替ルートを狙うターンにのみ優先してセットする。
- 配置優先順位は「目標より大きいカード > 目標ぴったり > 最大の妥協札」とする。
  - ただし、手札から出す候補は実際のアクティブエネルギーで支払えるものに制限する。
  - バトンタッチの場合は、登場先にいるメンバーのコストぶん支払いを軽減した実支払いコストで判定する。
  - 達成判定では上振れを認めるが、候補生成ではエネルギー不足の高コストを早いターンに置ける扱いにしない。
- 君ここ系のT4主目標を `13-7-2` に変更し、手札が多い場合のNS三神系上振れを `13-20-2` 代替として扱う。

制限:

- 現時点ではまだ実engine連動ではなく、ステージ継続、バトンタッチ元、控え室形成、ライブ成功率、必要ハート計算を厳密には再現していない。
- 特に10軸のT3到達率は、既存ステージから一部更新する実プレイより低く出る可能性がある。

### 試行モデル補正 20260729f

ステージを維持しない試行結果は実プレイと乖離しすぎるため、最優先基盤としてステージ継続モデルを追加した。

- 試行中に3枠のステージを保持する。
- 各ターン、既存ステージのうち目標形に近いカードは残す。
- 空き枠、または目標形から遠い枠だけを手札から更新する。
- 更新候補は、そのターンの目標/代替目標に対するスコア改善で評価する。
  - 20260731以降は、候補生成と達成判定を分ける。
  - 候補生成では `active/wait/energy_deck_remaining` を持ち、通常登場時にアクティブエネルギーを支払ってウェイトへ移す。
  - ターン開始時はウェイトをアクティブへ戻し、エネルギーフェイズぶんをエネルギーデッキからアクティブで追加する。
  - 各ターンに通常ドローを1回行う。T1もセットアップ後のドローを反映する。
  - Daydream Mermaid系のライブ成功時エネルギー増加はウェイトへ置き、次ターン以降のアクティブフェイズで使用可能にする。
  - 達成判定では、すでにステージに残っているカードや正規ルートで到達した上振れが目標以上なら達成扱いにする。
- 目標枚数を超える追加配置は、空き枠を埋めるだけでは行わない。
  - 以前はステージ枚数自体に小さな加点があり、`4` 単騎目標でも余分なメンバーを置いてT1平均コストが過大になっていた。
  - 20260731以降は、accepted target slot count までを評価し、目標改善にならない余剰配置を抑制する。
- 直近目標を満たしたあとは、追加で少しだけスコアが上がる配置よりも未来ターン用の手札とエネルギーを温存する。
  - 置き換え候補は、現在の低コストカードを下位目標の上振れとして固定しない。
  - 例: `13-2` を目指すターンでは、前ターンの7コストを2コスト目標の上振れとして保持せず、13コストへのバトンタッチ候補に含める。
  - 登場時に追加2コスト相当の低コスト召喚シグナルは、達成判定だけでなく配置探索の停止判定にも反映する。
- 低コスト追加登場効果は、ステージ枠数を超えない範囲で進行判定の仮想2コストとして扱う。

### Future target protection 20260731

実プレイでは、まず直近ターンに必要なカードを探すために手札交換し、必要カードが揃っている場合だけさらに先のターンのカードを保持する。
20260731時点では、以下を第一段として実装した。

- 現ターンの accepted target を満たしたら、そのターン内の追加配置を止める。
- バトンタッチ先候補生成を広げ、未来ターンで必要な高コストへの置き換えを候補外にしない。
- 仮想低コスト召喚を含めて現在目標を満たしているか判定し、余分なエネルギー消費を避ける。

次段階:

- マリガンとライブセット交換で、T3/T4の希少目標カードをより強く保持する。
- 「控え室からカードを手札に加える」効果も、同じ future target need score を使って必要札回収に接続する。

### Turn-aware future need 20260731

マリガン/ライブセット交換では、ターンごとの目標候補を平坦化せず、ターン構造を保ったまま必要度を計算する。

- 直近ターンの不足を最優先する。
- 直近が満たせる場合、T3/T4の希少カードを強く保護する。
- 採用枚数が少ない目標コストは、同じコスト値でも高く評価する。
- 2コスト/4コストのように採用枚数が多いカードは、必要数を超えている場合だけライブセット交換候補に戻す。
- Daydream Mermaid系のエネルギーブーストライブは、`2-4-2` 代替ルートが近い場合に保持/使用価値を上げる。

20260731時点では、マリガン、CPUのライブセット提案、UIなし試行のライブセット交換に同じ評価を接続した。
将来的な控え室回収効果では、同じ評価を「候補から何を手札に加えるか」に使う。

この変更により、以前の「毎ターン手札だけから盤面を作り直す」過大評価は無効になった。今後のオートプレイ精度改善は、このステージ継続モデルを土台に、バトンタッチ、控え室形成、ライブ成功率、必要ハート、実engine選択へ順次接続する。

### 試行モデル補正 20260729g

## Stage 1補正: ターン別達成率とライブスコア目標 20260729

ターン別達成率の見え方とライブスコア目標を整理した。

- `hit_rate` は、そのターン単独で現在のステージ形が目標を満たしているかを見る補助値。
- `cumulative` は、T1からそのターンまでの目標を連続して達成できた率。進行モデルの主評価はこの値を見る。
- 君ここ系でT4単独値がT3単独値より高くなるケースは、T3を外した後にT4の形だけ戻した試行が含まれるため。これは進行達成としては `cumulative` で弾かれる。
- 君ここ系のT4主目標は `13-7-2`、NS三神による上振れ代替は `13-20-2` として明示する。
- 5軸のT4は理想 `15-5-2` / `15-4-2`、妥協 `15-2-2` を受け入れ目標として扱う。
- ライブスコア目標をデッキ内の実ライブカードから推論する。T1は最低の正スコア、T2は次段階、T3以降は最大スコアを目標にする。
- ライブスコア達成判定は、効果処理用ライブとは分け、ライブセット交換で選ばれたライブカードのうち最大スコアのものを基準にする。

### 根本原因と構造改善 20260729

問題の根本原因は、ターン目標が複数の形で別々に管理されていたこと。

- `target_turns`: レポートに表示する主目標。
- `target_alternatives`: 実際の受け入れ目標。
- `target_goal_summary`: カード名と到達経路の表示用。
- `turn_success`: 試行中の判定用。

これらを別々に後処理していたため、5軸T4のように「判定は `15-5-2 / 15-4-2 / 15-2-2` だが、表示上の主目標は `2-15-2` のまま」という不整合が起きた。また、T4単独達成率を主評価のように読める表示だったため、T3未達からT4だけ戻した試行が進行成功に見える問題もあった。

再発防止として、ターンごとの評価単位を `stage_goal_plans` に統合した。

- `seed_shape`: 進行テンプレートやデッキ推論から出た元の形。
- `primary_shape`: レポートで主目標として表示する実評価の第一候補。
- `accepted_shapes`: 実際に成功扱いする全候補。

今後は、表示・判定・目標カード表示・マリガン/ライブセット参照をこの計画データから生成する。主目標だけの差し替えや、表示専用リストへの個別パッチは禁止する。

ライブスコア目標についても、レポート専用ではなくライブセット交換へ渡し、該当ターンのスコア目標を満たすライブを優先候補にする。レポートでは以下を分けて表示する。

- 盤面 `hit_rate`: そのターン単独の盤面形達成率。
- 盤面 `cumulative`: T1からそのターンまで盤面目標を連続達成した率。
- ライブスコア `hit_rate`: そのターン単独のライブスコア目標達成率。
- ライブスコア `cumulative`: T1からそのターンまでライブスコア目標を連続達成した率。
- `combined_cumulative`: 盤面目標とライブスコア目標の両方をT1から連続達成した率。

### 進行サポート札の検出 20260731

Daydream Mermaid のような進行補助札を、カード番号ではなく効果文から検出してプレイ方針へ渡す。

- `energy_boost`: エネルギーデッキからエネルギーを置くライブカード。5軸などの `2-4-2 + エネルギー追加` ルートでは、10コスト到達札に近い重要札としてマリガン/ライブセット交換で保護する。
- `energy_activate`: エネルギーをアクティブにするカード。10/11/13以上の到達ターンが近い場合に、通常の同コスト札より高く評価する。
- `cost_reduction`: 自身または登場に必要なコストを軽減するカード。高コスト到達候補として評価する。
- `free_member_play`: エネルギー/コストを支払わずにメンバーを登場させる文型。
- `overcost_member_play`: 支払ったコストより大きい、または一定コスト以下のメンバーを登場させる文型。
- `low_cost_summon`: コスト2以下などの低コスト追加登場。

これらは `progression_support_tags` としてデッキ内カードへ持たせる。現在はマリガン、ライブセット交換、レポートの `Special Signals` に接続済み。将来、控え室回収や山札検索の選択肢評価も同じ必要度評価へ接続し、「直近ターンの不足札を探す、不足がない場合は未来ターンの希少到達札/進行サポート札を保持する」挙動へ統一する。

20260731の確認では、Daydream Mermaid は `energy_boost` として検出され、5軸/10軸の序盤評価で need score `30.0` になった。前回モデルでは既にエネルギー追加ライブを交換対象から外す保護が効いていたため、同一 seed 200試行の達成率差分は `0.0` だった。今回の効果は、判断根拠の一般化とレポート表示、今後の回収/探索効果への接続点追加である。

### Decision Trace 20260803

達成率だけでは、どの選択で到達札を失ったか、あるいはそもそも引けていないかを判別しにくい。そのため、UIなしオートプレイの先頭N試行について、人間可読の選択ログを出力できるようにした。

出力対象:

- 初手とマリガン保持/戻し。
- マリガン時点の上位 need score。
- T1〜T3の開始盤面、開始エネルギー、通常ドロー。
- ライブセットで選んだカード、エネルギーブースト優先ターンか、ライブスコア目標。
- ライブセット前の上位 need score。
- MAIN前後のステージ、登場/置換されたカード、エネルギー消費。
- ターン結果、未達理由、ライブ成功時モデルで追加されたエネルギー。

確認用コマンド例:

```bash
python3 ./loveca_autoplay_report.py --root . --recent 3 --trials 50 --seed 29 --turns 4 --trace-trials 3 --outdir docs/reports/autoplay/decision_trace_20260803a --summary-csv docs/reports/autoplay/autoplay_trace_20260803a.csv --summary-json docs/reports/autoplay/autoplay_trace_20260803a.json
```

初回確認で見えた問題:

- 5軸サンプルで、T3目標 `2-11-2` に必要な11コスト札をライブセット交換に出してしまうケースがあった。
- これは「未来ターンの希少札保護」は入っているが、同一コストの採用枚数が多い場合に交換予算が緩み、直近ターンに必要な到達札まで交換候補へ戻るため。
- 次の改善では、ターン開始時点で「このターンの到達に必要な手札上の最高価値札」は、採用枚数が多くても原則交換しない保護を追加する。

## 精度改善ごとの比較指標 20260731

オートプレイ精度を変更した場合は、原則として同じデッキ、同じseed、同じ試行回数で変更前後を比較する。

seed運用:

- ロジック差分の回帰比較では、固定したbase seedセットを使う。
- 性能評価では、単一seedの試行回数だけを増やすより、複数base seedを固定セットで回して平均・最小・最大・ばらつきを見る。
- デッキ横断評価では、同じbase seedをそのまま各デッキへ使わず、base seedとデッキ識別子から派生したeffective seedを使う。これにより再現性を保ちながら、似たデッキ同士で同じシャッフル位置を踏む相関を避ける。
- 完全ランダムseedは探索には使えるが、後から同じ条件を再現しづらいため、レポート用途では固定seedセットを優先する。

基本コマンド:

```bash
python3 ./loveca_autoplay_report.py --recent 3 --trials 500 --seed 29 --turns 4 \
  --no-markdown \
  --summary-csv docs/reports/autoplay/autoplay_summary_after.csv \
  --summary-json docs/reports/autoplay/autoplay_summary_after.json \
  --compare-json docs/reports/autoplay/autoplay_summary_before.json \
  --compare-csv docs/reports/autoplay/autoplay_compare.csv \
  --compare-md docs/reports/autoplay/autoplay_compare.md
```

主に見る値:

- `tN_combined_cumulative_delta`: 盤面目標とライブスコア目標をT1から連続達成した率の差分。
- `tN_cumulative_delta`: 盤面目標をT1から連続達成した率の差分。
- `tN_live_cumulative_delta`: ライブスコア目標をT1から連続達成した率の差分。
- `tN_avg_stage_cost_delta`: 平均ステージコストの差分。
- `tN_top_miss_before/after`: 主な未達理由が改善でどう変わったか。

報告時は、最低限「比較対象、試行回数、seed、改善した指標、悪化した指標、悪化が許容できる理由または次の対応」を書く。

## マリガンの弱点ターン集中方針 20260803

実プレイ寄りのマリガンでは、単に各ターンの必要札を平均的に残すのではなく、「欠けると進行が大きく遅れるターン」「他ターンより構造上の達成率が低いターン」を重点的に底上げする。

初期実装では、T1からT3までのアクセス確率と手札保持価値を合算していたため、5軸で5コスト/Daydream Mermaidを引けていない局面でも、T3用の11コストを残す判断が強く出すぎた。5軸の11コストは十分な枚数があるため、この局面ではT2の5コストまたはDaydream Mermaidを探すために戻す価値が高い。

20260803時点の方針:

- 構築からT1-T3の理想盤面とaccepted targetを推定し、ターンごとに必要コスト帯の採用枚数と、そのターンまでの想定ドロー枚数から到達率を概算する。
- 初手に未確保のターンのうち、到達率が低く、採用枚数が少ないコスト帯または進行サポート札を要求するターンをボトルネックとして扱う。
- ボトルネックがある場合、全戻し時と一部キープ時のターン目標到達率を計算し、Decision Traceへ出す。
- 未来ターン用のカードでも、デッキ内枚数が十分あるコスト帯は弱点ターンの探索を妨げないよう戻しやすくする。
- 10軸の10コストのように採用枚数が少ない到達札は、同じ処理の中で希少札として保持価値を残す。

5軸の例では、T2のボトルネックを「5コストメンバー3枚 + Daydream Mermaid 4枚 = 7枚」として扱う。マリガン前に5コスト/Daydream Mermaidが無い場合、T2目標到達率は全戻しで約87.5%、2枚キープ相当で約74.6%となり、T2達成率だけを見るなら全戻しが有利。

## ユーザー例から反映したマリガン傾向 20260803

20260803のユーザー提示例を、カード番号専用ではなく進行タイプ・コスト・ライブ種別・ハート要求で一般化して反映した。

- 5軸では、5コストまたはエネルギーブーストライブが初手に無い場合、4コスト/2コスト/11コストだけを守らず全戻し寄りにする。5コスト + エネルギーブーストライブ + 2コストが見えている場合、4コストは代替ルート用として返しやすくする。
- 10軸では、10コストを最重要到達札として扱う。10コストが見えている場合は、2コスト2枚までと4コストを保持しやすくする一方、13/15コストの孤立キープを強く抑制する。
- 10軸で10コストが無い場合は、2コストを抱えるより4コスト中継札を1枚残して掘り直す。4コスト同士では、エネルギーブーストライブの要求色に寄与しやすい基礎ハートを持つカードを優先する。
- エネルギーブーストライブは、1〜3ターン目の進行札がほぼ揃っている場合は保持価値を上げる。単なるライブスコア札ではなく、次ターン以降のエネルギー制約を緩める進行札として扱う。
- 君ここ型では、7コストが無い初手は13コスト/2コスト/高スコアライブを守らず全戻し寄りにする。7コストがある場合は、0スコアのドローライブと、そのライブの要求色に噛む2コストを保持しやすくする。
- これらは「現在ターンの目標を満たす札を最優先し、揃っている場合だけ次ターン以降の希少札や進行サポート札を守る」方針として扱う。

20260803追加例で反映した傾向:

- 5軸で5コスト進行を取る場合、1ターン目に4コスト単騎へ逃げられないため、2コスト欠損は致命的に扱う。5あり/DMなし/2ありでは、5と2コスト2枚を残し、11以上は後引き期待で返す。
- 5軸でDM+4+2+2が揃う場合は、2ターン目DM成功がかなり見込めるため、DM/4/2/2を残す。11は後引き期待で返す。
- 5軸でDMはあるが4/5が無い場合は、4を探すために戻す枚数を確保し、2は質の高い1枚だけ残す。
- 5軸で5+DMはあるが2が無い場合は、2を引けない事故への逃げ道として4コストを1枚残す。
- 10軸で10はあるが4が無い場合は、4探索を優先し、10と質の高い2コスト1枚だけを残す。DMは4が無い場合には上振れ寄りで、安定志向では返しやすい。
- 10軸で10もDMも無く、4が1枚だけの場合は全戻し寄りにする。4が複数ある場合だけ、質の高い4を1枚残す余地を持つ。
- 君ここ型で7はあるが2が無い場合は、君ここ本体より2探索を優先し、7単体キープ寄りにする。
- 君ここ型で7+君ここ+2が3枚以上ある場合、安定志向では7/君ここ/2/2を残し、余分な2だけ返す。2が2枚以下の場合は、要求色に噛む2を1枚残す寄りにする。
- `PL!-pb1-018` 矢澤にこのような7コスト低コスト追加登場は、`energy_boost` ではなく `low_cost_summon` として検出する。進行上はエネルギー加速と同じく「ターン到達を底上げする進行サポート札」として扱い、`7-2-2` / `13-2-2` の上振れ代替shapeに接続する。

## ターン内処理順序の修正 20260803

20260803のライブセット判断ケース確認で、オートプレイの試行順序が実プレイとずれていることを確認した。旧実装では、通常ドロー後にライブセット交換を行い、その交換で引いたカードを同じターンのメンバー配置へ使えていた。これは「ステージ配置前に手札交換している」挙動になり、ステージ進行率を過大評価するため、以後の評価基準として使わない。

正本のターン内順序:

1. アクティブ/エネルギー/通常ドロー
2. メインフェイズのメンバー配置
3. ライブセットフェイズの最大3枚手札交換
4. ライブ成功時効果の簡易モデルを次ターン以降へ反映

この修正により、`20260803l` 以前の到達率は「ライブセット交換ドローを同ターン配置へ利用できる楽観値」として扱う。`20260803m` 以降を新しい比較基準にする。

ユーザー提示のT1開始時7枚手札ケースは、先にステージ配置を行った後のライブセット判断として照合した。5軸/10軸/君ここ型の12ケースは、期待されたステージ配置とライブセット対象に一致した。特に、ステージに置いた2コストを「余分な2」と判定して交換対象へ残す誤りがないことを確認した。

この段階ではライブスコア成功率の高度な推定は保留する。ライブセット判断は、まずステージ進行、次ターン以降の必要札探索、進行サポートライブの保護を優先する。ライブ成功確率や要求ハートの詳細評価は、ステージ進行評価が安定した後に追加する。

## ステージ維持と対策枠カード評価 20260803

T2以降のメイン配置では、空き枠がある限り既存ステージの置換を探索しない。`2-2` から `2-5-2` / `2-4-2` へ進む場合は、基本的に空き枠へ5コスト/4コストを追加する。2コストを一度バトンタッチで5/4へ変換し、別の2コストを手札から出し直すような動きは、手札消費と盤面維持の観点で不自然なため避ける。

need scoreでは、「目標より大きいコストなら何でも進行札」とは扱わない。実際のaccepted shapeに含まれるコストは保持対象にするが、単に大きいだけの13/15コストは、目標コストとの差が小さい場合を除いて代替進行札として過保護にしない。これにより、5軸に入っている13コスト対策枠のようなカードは、採用枚数が少なくてもライブセット交換で流しやすくする。

ライブセット交換では、未来ターンで必要なコストでも、ステージ+手札で必要数を超えている重複分は交換候補にできる。10軸T1で4コストが2枚残っているような場合、T2中継用の1枚を守りつつ、余剰の4コストは交換対象にする。

T3以降に目標スコアぴったりのライブが無い場合でも、手札に有効なスコアライブがあるなら、メンバーだけで交換枠を埋めずライブセット候補へ入れる。ライブ成功率の精密評価は後続課題だが、少なくとも成功可能性のあるライブを無視しない。

- オートプレイ用にルールを別実装しない。
- 効果解決が未実装または手動選択を要求する場面では、まずは安全な既定選択を記録し、後続で選択モデルを強化する。
