## 次バージョン候補の変更

### 追加

- 1デッキ用シミュレーターに通常リセットボタンを追加。
- リモート対戦用の1デッキ画面に、勝ち/負け/No Gameを記録してリセットするボタンを追加。
- 2デッキ用シミュレーターに、P1勝利/P2勝利/No Gameを記録してリセットするボタンを追加。
- 勝敗記録を `user_data/logs/loveca_match_results.jsonl` に追記するようにした。
- メニュー入口を、完全手動2デッキ対戦、CPUオート2デッキ対戦、UIなしオートプレイに分離。
- CPUオート2デッキ対戦に、片側CPU/両側CPU/自動進行の切り替えとCPU判断ログを追加。
- UIなしオートプレイCLIに、CSV/JSONサマリ出力を追加。
- オートプレイ方針/実装参照用の整理メモを追加。

### 変更

- 簡易設定の画面表示サイズを最大200%まで選択可能に変更。
- 起動時DB更新の画像取得ログで、既存リリースカード画像の不足件数とサンプルを表示するようにした。
- デッキ内容確認のカード詳細ポップアップで、カード効果を `effect_text_raw` 優先で表示するように変更。
- デッキ内容確認のカード詳細ポップアップで、コスト/スコアを整数表記へ整形し、ライブカードのスコア行も表示するように変更。
- デッキ編集画面の詳細分析ツールのタイトルを「詳細分析ツール」へ修正。
- ブレードハート内訳グラフで、ブレードハート専用texticon名を優先して参照するように変更。
- `PL!-bp3-012-PR` のような末尾レアリティ付き画像取得指定を、カード番号 `PL!-bp3-012` + 取得希望レアリティ `PR` として扱うように変更。
- UIアセットバンドル解凍許可リストに、ブレードハート用texticon候補名を追加。
- PRフォルダ内でも画像ファイル名のカード番号は完全一致で扱うように変更。`PL!-bp3-012-PR` は `PR/PL!-bp3-012-PR.png` を参照し、別カードである `PL!-PR-012` へ読み替えない。
- 公式Deck LogのLLC用CSSから `blade_heart01.png` から `blade_heart06.png`、`sp_all.png`、`sp_score.png`、`sp_draw.png` と各ON画像を取得し、texticonsへ追加。
- デッキ編集画面のブレードハート検索チップも、取得したtexticon画像を使って表示するように変更。
- UIアセットバンドル `loveca-ui-assets-20260722.zip` を再生成し、新規texticonを含めた。
- Wikiカードページの「収録状況」テーブルから `収録セット + カード番号 + レアリティ` を `printings_json` として保存するように変更。
- 画像manifest生成時に `printings_json` を参照し、収録セット名を既存の商品catalog/registryへ照合して、収録弾フォルダ + レアリティのURL候補を追加するように変更。
- デッキ編集画面で、アプリ上部ヘッダ、デッキ名/タグ、保存/保存して開始/キャンセルを固定ヘッダとして常時表示するように変更。
- デッキTSV/metadata内にHTMLエンティティが混入している場合、読込・保存時に通常文字へ戻すように変更。
- シミュレーション中のカード選択ポップアップで、上下ホイール操作でも横スクロールできるように変更。
- DeckLogデッキコード読込で、現行DeckLog APIのPOST取得と `list/card_number/num` 形式のJSON解析に対応。Playwright未導入のWindows環境でも `1U4B5` などのデッキコードを読み込めるように変更。
- プレビューカード取得で、公式ポスト集約ページのキャッシュ鮮度を短くし、ローカルDB未反映のプレビューカードを `[PREVIEW-INDEX-MISSING-DB]` として検出するように変更。
- プレビュー画像manifestに載っているが `preview_card_images` に実ファイルがないカードを、差分更新でも画像取得対象へ戻すように変更。
- プレビュー画像取得後にも不足が残る場合は、更新完了扱いにせずエラーとして不足件数とサンプルを表示するように変更。
- CPUのMAIN配置で、ターン目標コストより大きいカードを候補外にしないよう修正。目標より大きいカード、目標ぴったり、可能な限り大きい妥協の順で評価する。
- CPUのLIVE_SET判断ログに、ターンのライブスコア目標と実際に選んだライブカード番号/スコアを表示するように変更。
- CPUのMAIN終了判断を、目標達成済みの `main_complete` と、未達だが改善候補なしの `main_pass` に分離。

### 再発防止メモ

- 画像が半分程度しか取得されていないのに更新完了扱いになるケースでは、ログ上 `IMAGE-FETCH-MODE targets=0` となり、画像取得工程がスキップされていた。
- 既存DBに含まれるリリース済みカードの画像実ファイルが不足している場合は、差分更新でも再取得対象に戻す。
- 画像取得後にも不足が残る場合は完了扱いにせず、エラーとして不足サンプルを表示する。
- プレビューカード画像も同様に、manifest掲載済みだが `preview_card_images` に実ファイルがない場合は差分更新の対象へ戻し、取得後に不足が残る場合はエラー終了する。
- `PL!-bp3-012-PR` の正しい公式画像URLは `https://llofficial-cardgame.com/wordpress/wp-content/images/cardlist/PR/PL!-bp3-012-PR.png`。URLフォルダは `PR` でも、ファイル名側のカード番号 `PL!-bp3-012` は変更しない。
- 公式PR一覧には、カード番号内のエキスパンション部が `bp3` のままPRフォルダに収録される画像がある。manifest生成ではPR一覧を全カード番号に対して完全一致で追加走査し、アプリ表示側でもmanifest/実ファイルから完全一致で解決する。
- 公式カード検索画面では `heart01` から `heart06`、ブレードハート条件では `b_heart01` から `b_heart06` のクラス名が使われている。公式CSS/フォームAPIの直取得は404だったため、アプリ側は該当命名の受け皿を先に用意する。
- 再録/PR画像URL候補では、カード番号そのものを別カード番号へ変形しない。Wikiの収録状況から得た「収録弾フォルダ」と「レアリティ」を使って探索範囲を絞り、ファイル名側は収録状況のカード番号完全一致を維持する。
- DeckLogデッキコード読込では、ブラウザ画面と同じ `POST /system/app/api/view/{code}` を優先する。GETや静的HTMLだけに依存すると、Playwright未導入環境でカード0枚扱いになりやすい。
