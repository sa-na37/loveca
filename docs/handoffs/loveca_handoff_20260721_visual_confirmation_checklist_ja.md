# Loveca 目視確認チェックリスト 20260721

## 目的

このファイルは、runtime の状態差分ではなく、実ブラウザで見たときの表示・操作感を確認するための一覧です。効果処理そのものの合否とは分けて扱います。

## 前提

- 2デッキ用UIでは、同じ画面で両プレイヤーを操作するデバッグ/実機確認用途のため、相手手札・相手候補の秘匿は不要です。相手手札候補がactive側の選択UIに出ることは、2デッキ用UIでは不具合扱いしません。
- 情報秘匿が必要なのは、1デッキ用UIをリモート対戦用途で起動し、パブリックウィンドウを相手に見せる場合だけです。この場合は public view redaction が手札・山札・非公開pendingを隠すことを確認対象にします。
- 1デッキ版では相手個別カードstateを持たないため、相手成功ライブ置き場、相手ステージ、相手ライブカード置き場を参照する一部効果は手入力/手動確認が正式仕様です。画面上で「手動確認であること」と「発生源・実行中効果」が分かるかだけ確認します。

## 確認対象

### カード画像ボタン

- 候補カードがカード番号だけでなく、カード画像またはカード名つきで選べる。
- 1候補だけの場合でも、必要な選択 UI が省略されない。
- 複数候補のカード画像が重ならない。
- 選択ボタンの文字がはみ出さない。
- `PL!SP-pb2-001`: top5から選んだカードの「手札に加える / 空きエリアに登場させる」選択で、対象カードがカード番号単体ではなく表示名・画像と合わせて確認できる。
- `PL!N-bp5-029`: ハート付与先のステージメンバーが画像ボタンとして確認できる。

### 公開カード表示

- 公開されたカードと、選択可能なカードの違いが画面上で分かる。
- 通常の山札公開とエール公開で、見出しや集計欄が混ざらない。
- 控え室や成功ライブカード置き場など、公開領域から手札に加えたカードが public view 側でも公開手札として扱われる。
- 1デッキ用リモート起動のパブリックウィンドウでは、非公開の手札・山札・未公開ライブカード・非公開pending候補が裏面表示または枚数表示になっている。
- `PL!N-bp5-029`: 1段目で公開4枚全体が見え、選択可能な `中須かすみ` だけが操作対象として区別できる。

### メンバー下エネルギー表示

- メンバー下エネルギーのバッジがカードの背面に隠れない。
- 重なったエネルギーカードの右下に、枚数 `×N` が読み取れる。
- ステージカード、ハート、ブレード、下エネルギー表示が互いに重ならない。

### ライブ成功確認

- ALL ハート、エール由来ハート、合計ハートが画面上で正しく読める。
- 例: `ALL 0+1 / 合計 1` のような表示ズレ指摘が再発していない。
- ライブ成功時の複数自動効果がある場合、どの効果を解決するか分かる。

### 自動効果ポップアップ

- 発生源カードが分かる。
- 実行中の効果本文だけが表示され、別効果の全文が混ざらない。
- 条件達成/未達と処理結果が読める。
- `auto_order` で複数効果が並ぶ場合、選択肢の文言が区別できる。
- 1デッキ版の相手情報手入力効果では、手動確認であること、Apply/Skip または条件達成/条件未達の意味、発生源カードが分かる。

### 2デッキ相手干渉

- 相手手札破棄や相手手札ランダム公開で、表示された候補/公開カードを確認できる。2デッキ用UIでは秘匿不要なので、相手候補が見えること自体は問題にしない。
- 相手ウェイト、相手ドロー、相手エネルギーWAIT、相手控え室/山札、相手ポジションチェンジが発生したとき、どちらのプレイヤーへ反映されたかログや画面で追える。
- undo 後に、相手側の手札・山札・控え室・ステージ位置・エネルギー状態が見た目でも戻っている。

### 追加エール / エール公開カード消費

- `0枚で終了` / `選択を終了` が自然に押せる。
- 追加エール前の公開カードと、追加エール後の公開カードが同じ確認画面で判別できる。
- ドローアイコン処理済み枚数と、実際に引いた枚数が分かる。

### 登場・移動・バトンタッチ系

- 空きエリア登場のカード選択と登場先選択が分かりやすい。
- 元エリア登場時、戻る先のエリアが分かる。
- ポジションチェンジ後の移動時自動効果が、発生源つきで確認できる。
- バトンタッチ不成立時に、成功したように見えない。

## 完了条件

- 目視確認した項目は、対象カード・確認手順・結果を `docs/debug/loveca_debug_commands_current_updates_20260623.md` に追記する。
- 表示だけの問題は runtime の成功/失敗と混同しない。
- runtime 修正が必要な問題を見つけた場合は、目視確認メモから切り出して通常の実装修正タスクに戻す。
- Codex側のstate差分・ログ・pending検査で完了できる項目は、このチェックリストのユーザー目視待ちに残さない。
