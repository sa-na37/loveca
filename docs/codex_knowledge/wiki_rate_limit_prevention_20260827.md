# WIKIWIKI 429再発防止メモ

最終更新: 2026-08-27

## 再読タイミング

DB更新、商品ページ確認、公式ポスト確認、プレリリース画像取得を行う前に読む。

## これまで429を誘発した操作

- 商品ページを広く再取得した。
  - 過去には未発売商品をすべて `prerelease_product` として扱い、キャッシュがある商品まで踏みに行く設計になりかけた。
  - 対策: 未発売商品を全件強制取得しない。
- PBLL02商品ページから得たカードリンク20件を、そのまま個別ページプローブした。
  - 再録カードリンクも含めて踏んだため、`PL!-bp3-*` / `PL!-pb1-*` / `PL!-sd1-*` まで確認対象になり、途中から429が連続した。
  - 対策: 個別ページプローブは商品自身のカード番号だけに絞る。
- 個別カードページの公式Xリンク検知で、最大24ページまで読む設定だった。
  - 活動開始検知には1件見つかれば十分なので過剰。
  - 対策: 既定上限は5ページ、公式Xリンクを見つけたら即停止。
- 公式ポスト集約ページ更新後に、さらに多数の個別カードページを続けて踏んだ。
  - 対策: 公式ポスト集約ページでカード番号とX投稿が取れている場合は、それを優先し、個別ページ確認は補助に留める。

## 現行方針

- 商品一覧ページは通常TTLで確認する。
- 発売済み安定商品ページは長期キャッシュを使う。
- 発売済み商品の初回定期更新は `regular_checked_on` で一度だけ実施する。
- 未発売商品は次の3段階に分ける。
  - `prerelease_active_product`: 前回registryでカード個別ページから公式X投稿リンクが検知済み。商品ページは毎回新規取得を試みる。
  - `prerelease_nearest_probe`: 未発売商品のうち発売日が最も近い商品。商品ページは短TTLで確認し、個別ページ公式Xリンク検知は少数だけ行う。
  - `prerelease_dormant_reused`: それ以外の未発売商品。前回registryを再利用し、踏まない。
- 個別ページ公式Xリンク検知は、商品自身のカード番号だけに絞る。
- 個別ページ公式Xリンク検知は、最大5ページまで。1件見つけたら停止する。
- WIKIWIKI公式ポスト集約ページは、プレリリース画像取得の主経路として優先する。
- 429時にキャッシュがある場合はキャッシュ退避し、監査ログに残す。
- 429時に未キャッシュページの場合はスキップし、連続取得を続けない。

## 推奨取得ラグ

- DB更新のWIKIWIKIページ取得: 5秒以上。
- 起動時更新や利用者環境: 10秒程度を推奨。
- 公式ポスト集約ページ: 1ページだけなのでTTLを長めにし、頻繁な強制更新を避ける。
- X syndication JSON: WIKIWIKIとは別系統だが、0.25秒以上の間隔を維持する。
- 画像取得: manifest/preview manifestの既知URLだけを対象にし、heuristic探索はプレリリース中は避ける。

## やってはいけないこと

- 未発売商品を全件 `force_refresh=True` にしない。
- 商品ページから得たリンクを、再録含めて全件個別ページ確認しない。
- 429が出た直後に同じ範囲を遅延なしで再実行しない。
- 公式ポスト集約ページで取得できる情報を、個別ページ総当たりで取り直さない。
- プレリリース画像取得でheuristic URL探索を有効化しない。
